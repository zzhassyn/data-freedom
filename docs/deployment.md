# Vercel

## Конфигурация

- `index.py` — HTTP-вход Vercel, режим `WORKER_MODE=api`.
- `scripts/deploy.py` перед вызовом Vercel CLI запускает `scripts/build_static.py`, который копирует `web/index.html`, favicon, верхнеуровневые JS/CSS и SVG из `web/assets/` в `public/`. Каталог исключён из Git, но входит в загрузку Vercel; данные и API туда не копируются. Браузер перепроверяет актуальность файлов, а CDN хранит их отдельно для каждого deployment.
- `backend/Dockerfile.worker` — Python 3.12, ffmpeg и `python -m app.worker`, режим `WORKER_MODE=worker`.
- `vercel.json` — FastAPI в `iad1`, до 300 секунд на HTTP-запрос; один daemon в том же регионе, 1 GiB памяти, до 210 секунд на завершение при остановке.
- `.vercelignore` и `backend/.dockerignore` исключают ключи, локальные базы, окружения Python, тестовые артефакты и выгрузки результатов. Содержимое локальной SQLite автоматически не переносится.

Переменные сервера:

| Переменная | Назначение |
| --- | --- |
| `OPENROUTER_API_KEY` | Vercel Secret; доступна только серверу и worker |
| `JUDGE` | `openrouter` |
| `JUDGE_MODEL` | `google/gemini-3.8-flash` |
| `TURSO_DATABASE_URL` | Подключение базы, добавляется интеграцией Turso |
| `TURSO_AUTH_TOKEN` | Доступ к базе, добавляется интеграцией Turso |

Не задавайте `WORKER_MODE` на уровне всего проекта: HTTP-вход и Docker-образ выбирают разные режимы. Не добавляйте ключи в JavaScript, HTML или переменные с публичным префиксом.

Очередь, результаты и право владения фоновыми задачами сохраняются в Turso. Во время замены worker новый процесс ждёт освобождения права владения. Если платный запрос был прерван и его результат неизвестен, приложение отмечает его ошибкой; повтор запускается вручную, чтобы не повторять оплату автоматически.

## Повторный деплой

Из корня репозитория:

```powershell
vercel link --project data-freedom
python scripts/deploy.py --dry --json
python scripts/deploy.py --prod
vercel daemons list
vercel inspect data-freedom.vercel.app
```

Для деплоя используйте wrapper `scripts/deploy.py`: Vercel выбирает файлы `public/` из загружаемых исходников до запуска Python-сборки. Прямой `vercel deploy` после изменения интерфейса может загрузить старую копию ассетов. При ошибке подготовки wrapper завершает работу до загрузки.

В выводе `python scripts/deploy.py --dry --json` должны присутствовать актуальные файлы `public/`; там не должно быть `.env`, `.sqlite`, `.venv` и личных выгрузок. Добавляйте ключ интерактивной командой `vercel env add OPENROUTER_API_KEY --environment production --sensitive`, не вставляя его в историю команд. Изменённые переменные применяются при следующем деплое.

После деплоя проверьте `/api/health`, загрузку реестра и чек-листа, сохранение настроек и состояние daemon. Для HTML/CSS/JS проверьте совпадение с исходниками и `x-vercel-cache: HIT` при повторном запросе; `/api/bootstrap` должен сохранять `Cache-Control: no-store`. Проверка `modelOnline` использует запрос доступа к OpenRouter без генерации. Массовую оценку запускайте только для действительно нужных обращений: это оплачиваемые запросы к модели.

## Ограничения платформы

Vercel Daemons сейчас работают только в production. Preview подходит для проверки HTTP-части и интерфейса; фоновые задачи там не обрабатываются отдельным daemon. Preview и production не следует использовать одновременно для изменений одной базы.

На Hobby daemon ограничен общей квотой команды: 420 GB-часов памяти и 5 активных CPU-часов в месяц. Один постоянно работающий worker на 1 GiB расходует квоту памяти примерно за 17,5 суток; при исчерпании квоты Vercel останавливает daemon до следующего месяца. Автоматической платы за превышение квоты Hobby нет. Для постоянной работы в течение всего месяца потребуется другой режим фоновых задач либо подходящий план.

Если фоновая обработка временно не нужна, её можно остановить командой `vercel daemons scale worker iad1=0` и затем вернуть `vercel daemons scale worker iad1=1`. Сохранённые данные остаются в Turso; пока worker остановлен, новые фоновые задачи ждут запуска.

HTTP-функции Hobby ограничены 300 секундами и телом запроса 4,5 МБ. Локальный лимит загрузки приложения 20 МБ не отменяет ограничение Vercel. База Turso Starter использует собственные бесплатные квоты. Файловая система Vercel и daemon временная, поэтому она не используется как постоянная база.

Документация платформы: [FastAPI](https://vercel.com/docs/frameworks/backend/fastapi), [Daemons](https://vercel.com/docs/daemons), [квоты Daemons](https://vercel.com/docs/daemons/limits), [лимиты функций](https://vercel.com/docs/functions/limitations), [Turso](https://vercel.com/marketplace/tursocloud/database).
