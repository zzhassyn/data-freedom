# Интерфейс DataAvengers

Чистый HTML, CSS и JavaScript без сборки и фреймворков. Скрипты подключены обычными тегами `<script>`, поэтому страницу можно встроить веб-ресурсом Dynamics 365 или открыть любым статическим сервером.

## Запуск без бэкенда

```bash
python -m http.server 5500 --directory web
```

Откройте `http://localhost:5500/`. При старте интерфейс один раз проверяет `/api/health` с таймаутом 2 секунды. Статический файл возвращает `{"ok":false}`. Обращения, оценки, апелляции и чек-листы работают в этом браузере; загрузка JSON доступна, вкладка CRM скрыта. Пять размеченных обращений можно оценить повторно. Для остальных показана ошибка без подставленного результата.

## Запуск с бэкендом

Из папки `backend` после установки зависимостей по её README:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000
```

Откройте `http://localhost:8000/`. FastAPI раздаёт интерфейс и API с одного адреса. Обращения, оценки, апелляции, решения и версии чек-листа загружаются из SQLite и сохраняются на сервере. Они доступны после перезагрузки и в другом браузере. Реальная очередь оценки отдаёт частичные ответы, карточка обновляет их раз в 700 мс. Синхронизация получает свежий набор через сервер; её прогресс приходит потоком NDJSON. Номера обращений постоянны. Старые оценки и апелляции открывают сохранённый исходный транскрипт.

## Что сейчас работает

- Боковое меню сворачивается кнопкой, на телефоне выезжает поверх страницы. Аналитик видит обращения, апелляции, чек-лист и сводку. Проверяющий видит очередь и решённые апелляции, карточка обращения доступна ему для чтения.
- Реестр начинается с 65 обращений DEV: номер, дата и время, язык, канал, с чем обратились, итог. Поиск по номеру и тексту, фильтры галочками с чипами, страницы по 10, 25, 50 или 100 записей. Ссылки `#/?lang=KZ`, `#/?channel=voice%20call`, `#/?state=done` применяют фильтры. При наведении на итог плашка объясняет, из чего он сложился.
- «Загрузить обращения» открывает «Из файла»: выбор JSON или перетаскивание, проверка формата, предпросмотр состава. Форматы: массив записей, `{ "records": [...] }` или `{ "data": { "records": [...] } }`. Новые записи добавляются, изменённые транскрипты с тем же `conversation_id` обновляются, неизменные пропускаются. Номера сохраняются, прежняя оценка изменённой записи помечается устаревшей и исключается из сводки.
- Вторая вкладка «Из CRM» содержит источник и одну кнопку синхронизации. «Настройки источника» раскрывают поле «Набор обращений», по умолчанию DEV. «Сохранить» запоминает настройку, «Синхронизировать» также сохраняет введённое значение. Результат показывает новые, обновлённые и неизменные записи.
- Сводка показывает качество по критериям и языкам. Ячейки матрицы открывают реестр с фильтрами языка и готовой оценки. В рейтинге операторов служебные группы «Оператор не представился» и «Имя скрыто в записи» стоят после именованных операторов. Обращения без реплик оператора учитываются отдельной строкой под таблицей, если есть.
- Карточка диалога: транскрипт с ролями, системными событиями и паузами ожидания, итог, лента весов, критерии по секциям, объяснения, цитаты с переходом к реплике, проверенный участок, N/A с перераспределением веса.
- Живая переоценка: критерии заполняются по одному.
- Апелляция из карточки, очередь апелляций, решение проверяющего с предпросмотром нового итога, история «исходная оценка, решение, финальный итог».
- Редактор чек-листа: добавление и удаление критериев, название, правило оценки, тип ответа (да или нет, шкала, отметка без баллов), вес, ступени шкалы, N/A с условием, раздел. Проверки полей, сумма весов, сохранение новой версии и переключение активной версии.

В обоих режимах прямой адрес `#/lab/accuracy` открывает внутреннее сравнение ответов модели с ручной разметкой CSV. Ссылки на этот инструмент в меню и сводке нет. Пример файла находится в `data/gold-sample.csv`.

Без сервера оценки берутся из `data/mock-evaluations.js` для пяти диалогов: `p1-ru-001`, `p1-ru-007`, `p1-kz-003`, `p1-en-002`, `p4-ru-001`. На сервере используется настроенная реализация судьи; по умолчанию `JUDGE=fake` с теми же пятью заготовками. Для изменённого транскрипта прежний ответ не подставляется. Серверные результаты не смешиваются с данными браузера и не заменяются локальными при сетевой ошибке.

В режиме без сервера добавленные обращения и номера переживают перезагрузку страницы в `localStorage`. Встроенные 65 записей не копируются целиком: отдельно хранятся только пользовательские добавления и изменения встроенных записей. При запуске они объединяются с DEV по идентификатору. Данные браузера привязаны к адресу сайта; очистка хранилища сбрасывает их, но не удаляет записи из SQLite. В режиме с сервером реестр обновляет сведения при входе на экран и после загрузки или синхронизации.

## Устройство

| Файл | Что внутри |
| --- | --- |
| `styles/tokens.css` | Цвета, тени, радиусы, длительности |
| `styles/app.css` | Все компоненты и экраны |
| `js/api.js` | HTTP-клиент, таймауты, ошибки и определение режима |
| `js/core.js` | Форматирование, расчёт предпросмотра и фасад `DA.data` для API и браузерного хранилища |
| `js/ui.js` | DOM-помощник, иконки, боковая панель, тосты, переключатели, лента весов, плашка при наведении, фильтры |
| `js/registry.js` | Реестр диалогов |
| `js/upload.js` | Файл, предпросмотр, настройка источника и CRM |
| `js/card.js` | Карточка, апелляция, решение |
| `js/pages.js`, `js/review.js` | Апелляции, очередь и решения проверяющего |
| `js/insights.js` | Качество и операторы |
| `js/accuracy.js` | Внутренний экран сравнения с разметкой |
| `js/checklist-editor.js` | Редактор чек-листа |
| `js/app.js` | Боковое меню и маршруты через хэш |
| `data/` | Набор DEV от организаторов, чек-лист, тестовые оценки |
