# Интерфейс DataAvengers

Чистый HTML, CSS и JavaScript без сборки и фреймворков. Интерфейс работает с API: обращения, оценки и решения хранятся в SQLite. Сервер раздаёт страницу и API с одного адреса.

## Локальный запуск

Из папки `backend` после установки зависимостей по её README:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000
```

Откройте `http://localhost:8000/`. FastAPI раздаёт интерфейс и API с одного адреса. Обращения, оценки, апелляции, решения и версии чек-листа загружаются из SQLite и сохраняются на сервере. Они доступны после перезагрузки и в другом браузере. Реальная очередь оценки отдаёт частичные ответы, карточка обновляет их раз в 700 мс. Синхронизация получает свежий набор через сервер; её прогресс приходит потоком NDJSON. Номера обращений постоянны. Старые оценки и апелляции открывают сохранённый исходный транскрипт.

Загрузка файла и вкладка «Из CRM» доступны без ключа ИИ. Ключ нужен для оценки, резюме, перевода и других запросов к модели. Если он не настроен, обращения сохраняются, а окно загрузки сообщает, какие действия не запущены. Готовые ответы вместо них не подставляются.

Интерфейс обращается к `/api` на том же адресе. Открытие HTML-файла или статический сервер без API не создают отдельный режим работы: при недоступности сервера показывается ошибка и повтор загрузки. Встроенных обращений и оценок нет.

## Что сейчас работает

- Боковое меню сворачивается кнопкой, на телефоне выезжает поверх страницы. Аналитик видит обращения, апелляции, чек-лист и сводку. Проверяющий видит очередь и решённые апелляции, карточка обращения доступна ему для чтения.
- Реестр показывает загруженные обращения: номер, дату и время, язык, канал, краткое содержание и итог. Новая база начинается пустой. Поиск по номеру и тексту работает вместе с фильтрами; доступны страницы по 10, 25, 50 или 100 записей. Компактная панель у кнопки «Фильтры» показывает одну группу условий: состояние и отметки, апелляции, канал и язык, баллы, период или версия чек-листа. Баллы задаются включительным диапазоном от 0 до 100; даты включают оба выбранных дня. Ошибки диапазона показаны возле полей. Чип открывает свою группу для правки, крестик убирает условие. Фильтры сохраняются в адресе, возврат из карточки сохраняет поиск и страницу. Старые ссылки `#/?lang=KZ`, `#/?channel=voice%20call`, `#/?state=done` продолжают работать.
- Итоги, отметки и показатели в шапке реестра приходят из серверной аналитики для выбранной версии чек-листа. Переход из аналитики открывает точные обращения, а строка реестра ведёт к оценке, из которой взят итог. При наличии загруженного разбора плашка при наведении объясняет состав баллов. Если повторная оценка завершилась ошибкой, сохранённый готовый итог остаётся видимым вместе со статусом повтора. В колонке апелляций показано «Нет», ожидание решения или принятое решение; оба состояния могут присутствовать одновременно.
- «Загрузить обращения» открывает «Из файла»: выбор JSON или перетаскивание, проверка формата, предпросмотр состава. Форматы: массив записей, `{ "records": [...] }` или `{ "data": { "records": [...] } }`. Новые записи добавляются, изменённые транскрипты с тем же `conversation_id` обновляются, неизменные пропускаются. Номера сохраняются, прежняя оценка изменённой записи помечается устаревшей и исключается из сводки.
- Вторая вкладка «Из CRM» содержит источник и одну кнопку синхронизации. «Настройки источника» раскрывают поле «Набор обращений», по умолчанию DEV. «Сохранить» запоминает настройку, «Синхронизировать» также сохраняет введённое значение. Результат показывает новые, обновлённые и неизменные записи.
- Сводка открывается с «Общей сводки»: число обращений и готовых оценок, средний итог, причины для разбора и сравнение периодов при наличии сопоставимых данных. Фильтры периода, канала, языка и версии чек-листа применяются к серверным агрегатам. Вкладка «Качество» сохраняет матрицу критериев по языкам, итог, грубые ошибки и сведения об апелляциях. Ячейки и проблемные показатели открывают точные обращения в реестре. Отсутствующие оценки не считаются нулевыми.
- Во вкладке «Темы» кнопка «Определить темы» обрабатывает обращения текущих фильтров, для которых ещё нет актуального результата. Для каждого обращения определяется основная тема; общий справочник объединяет похожие запросы на разных языках. Сохранённые результаты используются повторно, изменение транскрипта требует новой классификации. Диаграммы показывают частоту тем и долю решённых вопросов среди известных исходов; решённые, нерешённые и неизвестные исходы разделены. Видно, сколько обращений ещё не разобрано или осталось без определённой темы. Редкие темы доступны в раскрывающемся разделе. Строки диаграмм раскрывают связанные обращения; повторный запуск продолжает обработку недостающих результатов.
- Вкладка «Операторы» содержит таблицу с количеством обращений, средним итогом, слабым критерием и грубыми ошибками. Строка открывает профиль с показателями, критериями для разбора и обращениями оператора. Таблица операторов и список обращений в профиле имеют отдельную пагинацию по 10, 25 или 50 записей. Переходы сохраняют фильтры и ведут к конкретным оценкам. Имена извлекаются из разговоров, поэтому такое объединение не подтверждает личность сотрудника.
- Карточка диалога: транскрипт с ролями, системными событиями и паузами ожидания, итог, лента весов, критерии по секциям, объяснения, цитаты с переходом к реплике, проверенный участок, N/A с перераспределением веса. Внизу находится закрытый по умолчанию блок «Сведения об обработке»: стоимость, модель, токены и время обработки. Неизвестная стоимость обозначается явно. Статусы ошибки, устаревшая оценка и действия повтора остаются рядом с результатом.
- Живая переоценка обновляет статусы и готовые ответы по мере получения результатов. Повтор отдельного критерия сохраняет остальные ответы.
- Пакетная оценка в реестре: выбор строк, диапазон с Shift, вся страница или все обращения по фильтрам. Панель показывает настоящие результаты очереди и сохраняет задачу при переходах и перезагрузке. Ошибочные обращения можно отфильтровать и повторить отдельно.
- Апелляция из карточки, очередь апелляций, решение проверяющего с предпросмотром нового итога, история «исходная оценка, решение, финальный итог».
- Чек-лист открывается как документ с правилами, долями в итоге и историей версий. Отдельный редактор ведёт через четыре шага: что проверить, как отвечать, насколько важно и когда не применять. Есть готовые шаблоны, отмена удаления, сохранение черновика и сводка изменений перед сохранением.
- «Сравнить версии» открывает две сохранённые версии чек-листа в направлении «Было → Стало». Видны добавленные и удалённые критерии, изменения названий, правил, типов ответа, шкал, условий N/A, нарушений, весов, разделов и порядка. Сравнение объясняет, какие изменения требуют новой оценки, а какие допускают пересчёт по совместимым сохранённым ответам. Переименование критерия тоже считается изменением правила. Просмотр не активирует версию и не запускает оценку; при единственной версии показано пустое состояние.
- Применение версии по адресу `#/checklists/apply/<version>`: выбор обращений, общая очередь и таблица «Было и стало». Новые результаты связаны с конкретной задачей. Изменение только весов пересчитывает итог без новых вызовов модели; изменённые правила требуют новых ответов. Повторно используется исходный ответ модели, поэтому ручные решения по апелляциям на новую оценку не переносятся.
- При импорте новые обращения автоматически оцениваются, новые звонки поступают в очередь расшифровки. Для уже существующих записей окно предлагает пропустить обработку или запустить её заново. Принятый сервером пакет не создаётся второй раз; несколько пакетов и расшифровка могут работать одновременно. Нижние уведомления можно скрыть, не останавливая задачи.
- Прогресс расшифровки виден, пока звонки обрабатываются. После завершения короткое уведомление исчезает; успешно обработанные звонки не оставляют отдельную кнопку в реестре. Если есть ошибки, из реестра можно открыть список и повторить только неудачные звонки.
- В звонке одна расшифровка: очищенная речь с исходными системными событиями CRM. Встроенный плеер строит волну по аудиоданным, запускает и останавливает запись у реплики, поддерживает скорость и клавиатурную перемотку. Системные события сохраняют своё время и не получают кнопок воспроизведения.
- Карточка получает резюме, перевод и советы через API, а проверяющий может запросить повторное мнение. Ошибка дополнительного блока не мешает основной работе. Решение по апелляции всегда сохраняет человек.
- Единый ИИ-ассистент доступен на разных экранах и при переключении роли. История и черновик сохраняются в текущей вкладке при переходах и сворачивании; новый чат очищается отдельной кнопкой. Текущий экран, открытое обращение, фильтры или сравнение версий помогают уточнить вопрос. Ассистент объясняет оценку, ищет обращения и цитаты, разбирает показатели качества и темы, сравнивает правила и предлагает улучшения ответа. Серверные инструменты работают только на чтение; ассистент не меняет оценки, апелляции или чек-листы. Ответ сопровождается источниками, точными цитатами и доступными переходами к обращениям или сравнению. Этапы обработки и текст ответа поступают потоком; доступны остановка и повтор после ошибки. Для ответов используются `OPENROUTER_API_KEY` и `AI_MODEL` либо `JUDGE_MODEL` из конфигурации сервера.
- RU / ҚАЗ / EN в меню меняет только подписи интерфейса. Открытые формы, черновики, выделение, задания и аудио сохраняются. Перевод диалога следует за языком интерфейса, если включён; запросы и кэш разделены по языку и источнику. Авторские правила чек-листа и исходные системные записи не заменяются автоматическим переводом интерфейса.

Прямой адрес `#/lab/accuracy` открывает внутреннее сравнение ответов модели с загруженной вручную разметкой CSV. Ссылки на этот инструмент в меню и сводке нет. На экране можно скачать пустой шаблон CSV для собственной разметки.

Реестр обновляет сведения при входе на экран и после загрузки или синхронизации. Данные SQLite не заменяются содержимым браузера при сетевой ошибке. В браузере сохраняются настройки интерфейса, черновики и сведения о фоновых задачах для восстановления их показа.

## Устройство

| Файл | Что внутри |
| --- | --- |
| `styles/tokens.css` | Цвета, тени, радиусы, длительности |
| `styles/app.css` | Общие компоненты; стили отдельных экранов находятся в соседних CSS-файлах |
| `js/api.js` | HTTP-клиент, таймауты и ошибки |
| `js/core.js` | Форматирование, расчёт предпросмотра и фасад `DA.data` для API |
| `js/ui.js` | DOM-помощник, иконки, боковая панель, тосты, переключатели, лента весов, плашка при наведении, фильтры |
| `js/i18n.js` | Каталоги трёх языков и явные привязки текста без пересборки экрана |
| `js/filters.js` | Общие условия фильтров, проверка диапазонов и ссылки на точные обращения |
| `js/registry.js` | Реестр, компактная панель фильтров, страницы и серверные показатели |
| `js/bulk.js` | Выбор, прогресс пакета и восстановление задачи |
| `js/apply.js` | Применение версии и сравнение итогов |
| `js/upload.js` | Файл, предпросмотр, настройка источника и CRM |
| `js/card.js` | Карточка, апелляция, решение и раскрываемые сведения об обработке |
| `js/assistant.js`, `styles/assistant.css`, `assets/assistant.svg` | Единый чат ассистента, история сеанса, источники и потоковый ответ |
| `js/stt.js`, `js/player.js`, `js/card-ai.js` | Фоновая расшифровка, плеер и дополнительные функции карточки |
| `js/pages.js`, `js/review.js` | Апелляции, очередь и решения проверяющего |
| `js/insights.js` | Серверная сводка, качество, темы, операторы и их обращения |
| `js/accuracy.js` | Внутренний экран сравнения с разметкой |
| `js/checklist-view.js`, `js/checklist-editor.js`, `js/templates.js` | Документ чек-листа, сравнение версий, редактор и шаблоны |
| `js/app.js` | Боковое меню и маршруты через хэш |
