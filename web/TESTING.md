На отдельном сервере `8016` с копией базы и текущим кодом проверена карточка `p1-ru-001`. Первое открытие вернуло уже сохранённые резюме и советы: два HTTP-запроса, ноль новых вызовов модели. Затем в отдельно разрешённом бюджете выполнен ровно один свежий запрос резюме; советы `ev_39` повторно взяты из кэша. Все POST, другие функции ИИ и дополнительные запросы за пределами бюджета были запрещены проверочным транспортом.

Настоящий компонент карточки показал тему из 28 символов на 5881 мс после открытия, пока запрос и итог ещё были пустыми. На 6100 мс появился запрос длиной 80 символов; на 6262 мс — 96 символов запроса и 45 символов итога. Итог дополнился до 79 символов; завершение сняло `aria-busy` на 6414 мс. Это последовательность фактически отрисованного текста. Частичный скриншот не успели снять до завершения потока, поэтому его не воссоздавали искусственно.

Учёт отдельной SQLite подтвердил одну новую запись вызова: 700 входных и 434 выходных токена, **$0,0021525**, задержка провайдера 5436 мс. Кэш советов не изменился. За два открытия было четыре разрешённых HTTP-запроса ИИ; дополнительных платных вызовов, записей из интерфейса и ошибок страницы не было.

- Две синхронизации подряд в каждом режиме. Живой API организаторов при первом импорте вернул 65 новых записей. Второй запрос показал «Новых 0, обновлено 0, без изменений 65». После изменения встроенного обращения файлом следующая живая синхронизация вернула `0 / 1 / 64`, затем снова `0 / 0 / 65`.
- Неизвестный набор сохраняется и при синхронизации показывает «CRM не ответила. Попробуйте ещё раз через минуту». Проверено восстановление настройки DEV.
- В рейтинге именованные операторы идут перед «Оператор не представился» и «Имя скрыто в записи». Отсутствие имени сопровождается предупреждением и подсказкой. В текущем DEV все 65 записей содержат оператора; бот без оператора и русские, казахские, английские маски проверены отдельными тестовыми записями, без изменения DEV.
- Клик по казахской ячейке матрицы открывает реестр с чипами «Казахский» и «Оценено». Отдельно проверены ссылки с `lang`, `channel`, `state` и клик после горизонтальной прокрутки мобильной таблицы.
- `#/lab/accuracy` открывается напрямую в обоих режимах работы, сохраняется при смене роли и перезагрузке. В меню и сегментах сводки его нет. Пример CSV загружается и даёт сравнение.
- В четырёх основных сценариях нет ошибок `console.error` и `pageerror`. Фавикон загружается. Синтаксис всех изменённых JS проверен через `new Function` в Node.

Дополнительный скрипт `verification/review_edges.py` проверяет ошибочный JSON, перетаскивание файла, укороченный транскрипт, сохранение устаревшей оценки без показа старых цитат на новом тексте, маски и исключение бота. Эти проверки используют явно созданные фикстуры, а не утверждают наличие таких данных у организаторов.

## Визуальная проверка

Проверены пиксели, отдельно от функциональных утверждений. На 1440 px окно CRM имеет одну главную кнопку, время синхронизации и тихое раскрытие настройки; служебные строки рейтинга не смешиваются с именами. На 390 px CRM и ошибки помещаются в нижнюю панель, сообщение об ошибке переносится, поле и действие доступны.

В предпросмотре файла на телефоне кнопка сжимала имя до многоточия. Кнопка перенесена под имя, название видно целиком, итог и основное действие остаются на экране. Удалён случайный текст `null` у отсутствующей строки подсказки. У матрицы устранён выход страницы за 390 px; прокручивается только таблица, длинные критерии переносятся и не накладываются на значения. Повторно просмотрены исправленные состояния.

Актуальные изображения: `verification/mobile-file-repaired.png`, `verification/mobile-matrix.png`, `verification/mobile-accuracy.png`, `verification/static-1440-operators.png`, `verification/static-390-operators.png`, `verification/backend-1440-crm.png`, `verification/backend-390-crm-error.png`. Изображения рейтинга сняты после файлового изменения, поэтому текущих оценок на них четыре. Это наблюдения агента, не измерение удобства для сотрудников Freedom.

## Как повторить

Команды запуска описаны в README. Для автоматического повторения запустите статический сервер на 5501 и бэкенд на 8000 с отдельным `DB_PATH`, затем из корня репозитория выполните `python web/verification/product_review.py` и `python web/verification/review_edges.py`. Нужен установленный Python Playwright с Chromium. Скрипты меняют записи и настройки проверочной базы.

Полный бэкенд: `.venv/Scripts/python.exe -m pytest -q` из `backend`, результат 167 passed. Контрольный набор организаторов пока не предоставлен: успех нового набора проверен тестами API, живой сетью проверены DEV и ошибка неизвестного набора. Полное подключение оценки и апелляций интерфейса к API остаётся вне этих правок.
