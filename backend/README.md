# DataAvengers: FastAPI и SQLite

Бэкенд для Python **3.10+**, один процесс. Все данные, оценки, задачи, апелляции, версии, ручная разметка и ИИ-кэш сохраняются в SQLite. Готовые шаги оценки не повторяются после перезапуска.

## Установка и запуск

Из папки `backend` в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

CRM, загрузка файлов, реестр, чек-листы и сохранённые данные доступны без ключа OpenRouter. Для оценки, резюме, советов, перевода и расшифровки укажите `OPENROUTER_API_KEY` в `.env`; в примере уже выбраны `JUDGE=openrouter` и `JUDGE_MODEL=google/gemini-3.8-flash`. Затем запустите:

```powershell
uvicorn app.main:app --port 8000
```

Если активация окружения запрещена настройками PowerShell, используйте `.\.venv\Scripts\python.exe -m pip install -r requirements.txt` и `.\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000`. Ключ остаётся в локальном `.env`, который не входит в Git.

Интерфейс: <http://localhost:8000/>. OpenAPI: <http://localhost:8000/docs>. Для доступа по сети добавьте `--host 0.0.0.0`. Не запускайте несколько `--workers`: очередь рассчитана на один процесс. CORS разрешает локальные `localhost` и `127.0.0.1` с любым портом.

Сервер раздаёт папку `../web`. Интерфейс использует REST API для обращений, загрузки JSON, синхронизации CRM, оценок, апелляций, решений и версий чек-листа. Частичные результаты очереди появляются в карточке по мере готовности. Результаты сохраняются в SQLite и доступны из другого браузера.

Все изменяющие запросы требуют `Content-Type: application/json`, включая POST без параметров (передавайте `{}`). Исключение: `POST /api/gold` принимает `text/csv`. Неподходящий тип получает 415 `unsupported_media_type`. При наличии `Origin` разрешён тот же источник либо `http://localhost` / `http://127.0.0.1` с любым портом; без `Origin` заголовок `Sec-Fetch-Site`, если он есть, должен быть `same-origin`. Чужой источник получает 403 `forbidden_origin`. Серверные клиенты без обоих заголовков работают с указанным типом содержимого.

## Настройки

Рабочая конфигурация задаётся в `.env` по примеру `.env.example`. Пути разрешаются относительно `backend`, независимо от рабочей директории. Отсутствие ключа или модели вызывает понятную ошибку соответствующей ИИ-операции; сервер и сохранённые данные остаются доступны. Автоматического перехода на заготовленные ответы нет.

| Переменная | По умолчанию / назначение |
| --- | --- |
| `DB_PATH` | `./data/cqa.sqlite`, создаётся при запуске |
| `ORG_API_URL` | Ссылка организаторов без `group_id`; включена в `.env.example` и настройки по требованию задания |

| `JUDGE` | `openrouter` по умолчанию; `real` подключает отдельный ML-модуль |

| `JUDGE_MODEL` | `google/gemini-3.8-flash` в `.env.example`; имя передаётся провайдеру из настройки |
| `JUDGE_TEMPERATURE` | `0` для основной оценки |

| `LLM_PRICE_IN`, `LLM_PRICE_OUT` | Тарифы отдельного ML-адаптера за миллион токенов; OpenRouter возвращает фактическую стоимость в `usage.cost` |
| `AUTO_SUMMARIZE` | `1`: при настроенной модели после импорта резюме рассчитываются в фоне с более низким приоритетом, чем оценки; `0` отключает |
| `AUTO_EVALUATE_IMPORTS` | `true`: при настроенной модели новые обращения сразу поступают на оценку |

Если `JUDGE` не задан, используется `openrouter`. Основной ответ, исправление и независимая проверка делят один таймаут операции модели, по умолчанию 180 секунд. Импорт источника ограничен 60 секундами и одним повтором. Запросы с телом ограничены 20 МБ, размер `gold.csv` ограничен 5 МБ. В режиме OpenRouter `health` проверяет ключ через `/api/v1/key`, без генерации текста, с таймаутом 3 секунды и кэшем 20 секунд. Это проверка доступа, а не качества оценки или доступности каждого выбранного провайдера.

Аудиопрокси принимает только HTTPS. Хост после приведения к нижнему регистру и удаления конечной точки должен точно совпадать с разрешённым значением либо быть его поддоменом по границе точки. Проверяются страница плеера, адрес `<source>` после `urljoin` и каждый редирект (до трёх на цепочку). Перед подключением проверяются **все** адреса `getaddrinfo`: непубличные, частные, loopback, link-local, multicast, unspecified и reserved запрещены. Соединение идёт на проверенный IP с исходными Host и TLS SNI/проверкой сертификата, без повторного DNS-разрешения хоста и без прокси из переменных окружения. DNS-проверка ограничена 10 секундами. При импорте/загрузке недопустимая аудиоссылка заменяется на `null`; поле `audioRejected` содержит число таких ссылок, а аудиомаршрут возвращает `no_audio`. Остальные данные диалога сохраняются.

## Подключение модели

`JUDGE=openrouter` выбирает `app/judge/openrouter.py` и `app/ai/openrouter.py`. Судья получает полный исходный разговор и один критерий, возвращает `JudgeResult`: ответ, объяснение, точные цитаты, проверенный участок, причину N/A, виды грубых ошибок, usage и фактическое имя модели. Общие Pydantic-типы находятся в `app/models.py`; Python использует `snake_case`, HTTP использует `camelCase`.

Основной режим принудительно вызывает инструмент `submit_verdict` с JSON-схемой. Сервер проверяет допустимые ответы, диапазоны, виды нарушений и наличие каждой цитаты в указанной исходной реплике. При неверном содержимом допускается один исправляющий запрос с причиной отказа. Сетевая ошибка не запускает молчаливый повтор платного запроса с неизвестным исходом.

Завершение `finish_reason=length` означает исчерпанный лимит ответа и показывается отдельно от ошибки схемы. Такой ответ не повторяется автоматически с тем же лимитом. Полученные usage и стоимость сохраняются. В журнал попадают только категория ошибки, причина завершения и числа токенов, без разговора, ответа модели или скрытого рассуждения. Лимит 8192 оставляет место для рассуждения и структурного ответа; уровень рассуждения модели не переопределяется.

В парной пробе 7 ноября 2026 года проверены пять одинаковых задач в двух форматах: пять ответов `tool` и пять `schema`. Все десять прошли проверку, ответы каждой пары совпали. Общая стоимость составила $0.04613175; среднее время было 5,447 с для `tool` и 5,225 с для `schema`. Выбран `tool`; эта небольшая проба не доказывает превосходство формата в надёжности или точности и не измеряет стоимость полного диалога.

Для шкального ответа и для «Нет» по пропущенному действию судья делает дополнительную проверку при температуре `0.3`. Если ответы различаются или любой вывод имеет `confidence=low`, сохраняется `needsReview=true`; основной ответ автоматически не заменяется. С исправлениями возможно до четырёх HTTP-вызовов на критерий в пределах общего таймаута. Число критериев поэтому не равно числу оплаченных запросов.

Полученные от OpenRouter токены и `usage.cost` учитываются и при отклонённом ответе. Повторы накапливают затраты, а переиспользованный критерий не создаёт новый вызов. Для reuse должны совпасть транскрипт, ID и содержание критерия, а также настройки модели и инструкций. Изменение только веса позволяет пересчитать баллы без модели. После апелляции повторно используется исходный модельный ответ. У каждого критерия хранится своё имя модели; старые заготовки не переиспользуются и не показываются как реальные оценки.

Идентичность v2 включает модель, режим ответа, температуры, промпты, подсказки, форму вердикта, сборку запроса и проверку ответа. Изменение транспортного таймаута или лимита токенов не отменяет уже проверенные ответы. Точные отпечатки двух прежних реализаций разрешены в [cache-compatibility.json](app/judge/cache-compatibility.json) только для соответствующего текущего семантического отпечатка после проверки различий исходного кода. Неизвестные версии не получают совместимость. Сохранённые идентификаторы оценок не переписываются. При изменении политики выбора основного ответа или независимой проверки требуется новая версия `_SEMANTIC_CONTRACT_VERSION`.

`JUDGE=real` служит точкой подключения отдельного ML-модуля. Подготовленные ответы находятся только в `tests/` и передаются тестовому приложению через явную подстановку провайдера. В рабочем приложении такого режима нет; ошибка подключения модели возвращается клиенту.

## Как оцениваем

- Оценивается оператор. AIM, клиент и системные события дают контекст; действия бота не засчитываются оператору. Объяснение всегда на русском, цитаты сохраняют исходный язык и маски.
- Подтверждение личности системой на RU, KZ или EN учитывается независимо от языка остальных реплик. Для исходного правила идентификации также подходит сверка как минимум двух идентификаторов с подтверждённым совпадением: ФИО плюс дата рождения, ИИН, номер счёта, кодовое слово или телефон. Запрос данных без подтверждения недостаточен. Проверка должна предшествовать раскрытию данных счёта или защищённому действию; общая навигация и вопросы о тарифе её не требуют.
- Маска имени оператора в его представлении считается представлением. Для исходного контакта в звонке N/A разрешается только при подтверждённом системным событием начале записи после соединения до первой реплики оператора и отсутствии приветствия в этой реплике. Позднее возобновление записи и одно лишь отсутствие приветствия не включают исключение.
- Базы знаний Freedom у модели нет. Она оценивает логику, полноту и следующий шаг по разговору. Непроверяемый внешний факт не объявляется ошибкой; существенная нехватка данных отмечается `confidence=low`. N/A применяется по условию критерия, а не вместо неуверенности.
- Текущее правило, тип, условие N/A и ступени шкалы определяют ответ, включая новый или изменённый критерий. Уточнения восьми исходных правил подключаются только после сверки `contentHash` с исходным текстом; смена веса их сохраняет, изменение смысла отключает. Исключение контакта в звонке защищено той же проверкой.

Системная инструкция находится в `app/judge/prompts/system.md`, уточнения в соседних файлах критериев. `hints.py` детерминированно отмечает первую реплику оператора, системные подтверждения личности, паузы, закрытие разговора и начало записи. Эти признаки помогают найти свидетельства, но сами не назначают баллы. Итог рассчитывает сервер через `Decimal` с округлением половиной вверх; грубая ошибка передаётся отдельным флагом.

## Резюме, советы и кэш

Резюме содержит тему, запрос клиента, итог и имя оператора либо `null`, если оно не установлено из текста. Советы относятся только к бинарным «Нет» и неполным шкальным ответам, с примером фразы на языке разговора. Повторное мнение учитывает спорный критерий и комментарий аналитика; решение остаётся за проверяющим. Помощь с критерием возвращает правило, условие N/A и ступени согласно выбранному типу.

Резюме и советы поддерживают настоящий поток провайдера. Для `/summary?stream=true` и `/coaching?stream=true` ответ имеет `Content-Type: application/x-ndjson`; каждая строка представляет отдельное событие:

```json
{"type":"partial","value":{"topic":"Промежуточный текст"}}
{"type":"done","result":{"topic":"Тема","request":"Запрос","outcome":"Итог","operatorName":null}}
```

Для советов `value` и итоговый `result` содержат `tips:[{criterionId,tip,example}]`. При ошибке после начала потока приходит `{"type":"error","error":{"code":"...","message":"..."}}`; HTTP-статус к этому моменту уже может быть 200. `partial` отражает полученный текст и не считается готовым результатом. Только проверенный итог сохраняется в кэш и отправляется как `done`. Закрытие потока отменяет незавершённый запрос. Без `stream=true` эти маршруты возвращают обычный JSON.

Постоянный кэш проверяет хэш исходного разговора или оценки и идентичность провайдера. Для OpenRouter она включает модель и версию инструкций, поэтому прежние заготовки или результаты другой модели не становятся текущим резюме или советами. Перевод дополнительно разделён по источнику и целевому языку. Изменение оценки после апелляции обновляет советы; старые оценки сохраняют собственный снимок транскрипта. Одинаковые запросы используют общий результат, `?refresh=1` явно запускает пересчёт.

## Источник CRM и повторная синхронизация

Таблица `settings` хранит `sourceGroupId` (по умолчанию `DEV`), `lastSyncAt` и `lastResult`. До первого успеха последние два поля равны `null`. Смена набора сбрасывает сведения о последней синхронизации; повторное сохранение того же набора их сохраняет. Настройки переживают перезапуск сервера.

Каждая синхронизация заново обращается к API организаторов с сохранённым `group_id`. Дедупликация общая для файла и CRM по `conversation_id`: новый диалог добавляется, изменённый транскрипт обновляется, неизменный входит в `unchanged`. Старая оценка сохраняется в истории и получает `lastEvaluation.status=stale` в реестре; её снимок транскрипта не меняется. При неизменном транскрипте сохраняются время импорта и актуальность оценки. Метаданные источника и аудиоссылки могут обновляться. Удаление записи из внешнего набора не удаляет её из реестра.

Полный импорт из API атомарно сохраняет `datasetRoster:<groupId>` с исходными ID, хэшами транскриптов и временем получения. Противоречащие `dataset_group_id` или `total_records` отклоняются до записи. Частичная загрузка не заменяет полный состав набора. Выгрузка использует сохранённый состав, поэтому старые лишние строки реестра в неё не попадают.

Список, карточка обращения и снимок для апелляции возвращают стабильные `number` и `startedAt`. Номер назначается сервером при первом импорте и сохраняется при обновлении. У звонка дата берётся из первой ISO-реплики, у чата без календарной даты используется время первого импорта. `startedAt` хранится в ISO UTC и также сохраняется при обновлении. При запуске существующая база получает эти поля из прежнего порядка записей и сохранённого времени; номера не зависят от браузера и фильтров.

В кратком списке есть `transcriptHash` и `audioUrl`: они позволяют проверить актуальность сохранённого в браузере транскрипта без повторного получения всех полных диалогов. При смене аудиоссылки хэш текста не меняется.

Обычный `POST /api/source/sync` возвращает JSON после завершения. Для прогресса интерфейс передаёт `Accept: application/x-ndjson`: события `fetching`, затем `importing` с `processed` и `total`, затем `done` с `result`. Счётчик отражает обработанные записи; успех отправляется только после фиксации транзакции. Событие `error` содержит безопасную ошибку «CRM не ответила. Попробуйте ещё раз через минуту». При ошибке прошлый успешный результат остаётся сохранённым. Синхронизации и смена источника выполняются последовательно, импорт записей и сохранение результата атомарны.

Все три пути импорта возвращают `newConversationIds`, `existingConversationIds`, `imported`, `updated`, `unchanged`, `sttQueued`, `sttConversationIds` и `evaluationJob`. При настроенной модели новые обращения автоматически оцениваются по активному чек-листу с `reuse:false`; новые звонки с аудио также поступают в очередь расшифровки. `evaluationJob` содержит `{jobId, evaluationIds, checklistId, checklistVersion, reuse:false}` либо `null`, если оценка не запущена. Отключить автоматическую оценку можно через `AUTO_EVALUATE_IMPORTS=false`; по умолчанию она включена.

В режиме OpenRouter без ключа импорт сохраняет диалоги и возвращает успешный ответ, но не создаёт задачи ИИ-обработки. Если включённая функция недоступна, ответ дополнительно содержит `processingUnavailable:{code:"model_unavailable",features:[...],message:"..."}`; список `features` включает недоступные `evaluation`, `summary` или `transcription`. Ручной запуск недоступной оценки, резюме или расшифровки возвращает 503 `model_unavailable`. Готовые данные, CRM и загрузка файлов остаются доступны.

Существующие идентификаторы не создают новые обращения. Их текст и метаданные обновляются, но повторная оценка, резюме и расшифровка автоматически не запускаются. Интерфейс показывает число уже имеющихся записей и предлагает обработать их заново; после согласия использует обычный запуск оценки и `POST .../transcription/retry` с `{"force":true}`. Повтор импорта после потери HTTP-ответа также не запускает вторую обработку существующих записей. Уже принятую оценку можно найти в реестре и истории.

## JSON для сдачи результатов

В корне репозитория используются `results/dev/results.json` для всех 65 записей DEV и `results/prod/results.json` для 10 контрольных чатов. Перед экспортом выполните полную синхронизацию нужного набора: она сохраняет точный состав и хэши. Если запись изменилась после этой синхронизации, экспорт остановится до повторного получения набора.

При работающем сервере из папки `backend`:

```powershell
python scripts/export_results.py --group DEV --out ../results/dev/results.json --timeout 1200
python scripts/export_results.py --group "<group_id_контроля>" --out ../results/prod/results.json --timeout 1200
```

Подставьте выданный `group_id` во вторую команду. `--base-url` по умолчанию равен `http://127.0.0.1:8000`; без активации окружения используйте `.\.venv\Scripts\python.exe`. Скрипт обращается к работающему серверу, поэтому не запускает вторую очередь SQLite или расшифровку. По умолчанию он оценивает отсутствующие результаты через существующую очередь с `reuse=false`; `--no-evaluate-missing` запрещает новые вызовы. Ожидание по умолчанию составляет 600 секунд, допустимый максимум 1800.

Скрипт сначала читает `/api/export/organizers/manifest?groupId=...`, затем передаёт его `sourceHash` в `POST /api/export/organizers`. Тело запроса: `{"groupId":"DEV","evaluateMissing":true,"sourceHash":"...","timeoutSeconds":1200}`. Необязательный `sourceHash` защищает от смены набора между чтением состава и экспортом. По умолчанию API использует `evaluateMissing:false`; выгрузка из реестра также не запускает модель. Ответ скачивается как `results.json`.

Документ строго следует JSON 1.0: `schema_version`, `team_name:"DataAvengers"`, `model:{mode:"external_api",name:"..."}` и `results`. Используются восемь критериев исходной версии 1, даже когда активна другая версия. Коды `needs`, `closing`, `gross` превращаются в `discovery`, `closure`, `critical`; остальные сохраняются. Бинарные значения становятся `true`/`false`, допустимый N/A становится `null`, шкалы сохраняют ступень до веса. `evidence_turns` содержит исходные `turnIdx+1`, включая клиента, AIM и системные события.

После апелляции берётся `original.answer`, а не решение человека. Итог и `critical_flag` пересчитываются по исходным ответам; N/A исключает вес, округление выполняется половиной вверх до двух знаков. Грубая ошибка не обнуляет итог. `model.name` перечисляет реальные модели каждого критерия. Заготовки и старые оценки без проверяемого происхождения не включаются как готовый результат.

Каждый ID остаётся в файле. Отсутствующая, незавершённая или ошибочная оценка получает `status:"error"`, `criteria:[]`, `score:null` и причину. Если ни одной реальной модели установить нельзя, `model.name` остаётся пустой строкой; вымышленное имя не подставляется. Скрипт печатает количество таких строк. Валидность JSON не означает отсутствие ошибок оценки.

Перед записью проверяются точный состав набора, уникальность ID, восемь критериев, отсутствие лишних полей, типы, номера реплик, исходные цитаты и итоговый балл. Файл записывается в UTF-8 и атомарно заменяет выбранный путь только после успешной проверки. При неверном документе существующий файл остаётся неизменным. На контроле порядок действий: получить набор, синхронизировать, оценить 10 чатов, выгрузить и проверить ошибки, затем сделать commit и push обоих файлов до стоп-кода.

В требованиях есть неразрешённое расхождение: ответ организаторов допускает N/A для контакта в звонке с поздним началом записи, но таблица формата JSON разрешает для `contact` только `true`/`false`. Строгая выгрузка сохраняет такой диалог как `status:"error"` с причиной; она не превращает N/A в «Нет» и не выпускает запрещённый `null`. Контрольный набор по условиям содержит только чаты.

## Расшифровка звонков

`STT_ENABLED=true` включает отдельную очередь с `STT_CONCURRENCY=3`. Ключ `OPENROUTER_API_KEY` хранится только в `backend/.env`. Аудио передаётся во внешний сервис **OpenRouter, затем ElevenLabs**; маскировка ответа не отменяет передачу аудиозаписи. Модель по умолчанию `STT_MODEL=elevenlabs/scribe-v2`, стоимость вычисляется по `usage.seconds × STT_PRICE_PER_SEC` (по умолчанию `0.0000611` доллара за секунду, около $0.22 за час). Чтобы отключить новые задачи и скрыть собственную расшифровку, задайте `STT_ENABLED=false` и перезапустите сервер. Без ключа новые задачи не создаются, ручной запуск возвращает 503 `model_unavailable`; основной сервис продолжает работать.

Шаги задачи: `queued → download → transcribe → mask → build → done` либо `failed`. Прогресс этапа распознавания оценивает ожидание, а не полученные от провайдера проценты; общий прогресс интерфейса считает завершённые звонки. Один вызов ограничен 120 секундами, повторяется только один раз после 429/5xx с паузой 3 секунды. Обычный повтор готовой задачи её не оплачивает заново; для осознанной повторной расшифровки нужен `force:true`. Очередь и готовые результаты привязаны к `transcriptHash`, устаревший работник не может заменить результат изменённого разговора.

Скачивание использует ту же защиту адресов, DNS и перенаправлений, что аудиопрокси. MP3 временно хранится на сервере и удаляется при завершении или отмене. `ffprobe` читает заявленную длительность, `ffmpeg` полностью декодирует файл. Если доступная часть короче больше чем на 5 секунд, возвращаются `incomplete:true` и обе длительности; доступная часть всё равно расшифровывается. Без FFmpeg сохраняется `audioCheck:"unavailable"`, проверка обрыва не заявляется выполненной.

До сохранения текст проходит маскирование ИИН, карт, телефонов, личной почты, кодов, адресов и скрытых у организаторов имён. Неуверенно выровненный ограниченный фрагмент скрывается целиком; если безопасную границу установить нельзя, задача завершается ошибкой без публикации текста. Сырые слова и текст не попадают в обычные таблицы, HTTP-ответы или журнал. `STT_KEEP_RAW=false` по умолчанию; `true` отдельно создаёт таблицу `transcriptions_raw` с исходными ответами, содержащими личные данные. Возврат к `false` удаляет эту таблицу при запуске. Автоматическая оценка всегда получает исходный транскрипт организаторов.

После перезапуска очередь продолжает задачи, ещё не дошедшие до платного вызова. Прерванные `transcribe`, `mask` или `build` отмечаются ошибкой и требуют явного повтора: при неизвестном результате внешнего запроса сервер не делает новый платный вызов молча. Во время штатной остановки фоновые задачи отменяются и временное аудио удаляется. Запускать приложение следует одним процессом, как и очередь оценок.

Роль голоса определяется по совпадениям с исходными репликами. Сильное лексическое совпадение отдельной реплики может уточнить её `role`, если распознаватель объединил автоответчик и клиента под одним голосом. Порядковое сопоставление `orgIdx` само по себе не считается доказательством роли. Это сопоставление текста, а не независимая проверка говорящих на слух.

В интерфейсе один диалог: распознанная речь дополняется исходными системными событиями CRM с их собственным временем. События не объявляются результатом распознавания и не получают кнопок воспроизведения. Если готовой расшифровки нет, показывается исходный диалог; историческая оценка сохраняет свой снимок.

## Перевод диалога

`GET /api/conversations/{id}/translation?targetLanguage=EN&source=transcription` возвращает `turns`, `targetLanguage`, `source` и `sourceHash`. По умолчанию используются `RU` и `canonical`. Для языка, совпадающего с языком обращения, возвращаются исходные реплики без модельного вызова. Источник `transcription` доступен только для готового очищенного текста текущего разговора. Необязательный `sourceHash` отклоняет запрос, если показанный текст уже изменился.

Все направления перевода используют `TRANSLATION_MODEL` и ключ OpenRouter, отдельно от модулей судьи и других ИИ-функций. Отсутствие ключа возвращает недоступность перевода. Результат и ожидающий запрос разделены по обращению, источнику, хэшу, целевому языку и модели. Повторное переключение языка переиспользует готовый результат или тот же выполняющийся запрос.

Обозначения скрытых данных перед отправкой заменяются непрозрачными метками. Сервер проверяет их точное количество и принадлежность репликам, затем восстанавливает исходные обозначения. Дополнительно проверяются все ID, отсутствие лишних или пропущенных реплик, обычный текст и неизменность масок. Некорректный результат не попадает в кэш. Автоматического платного повтора нет; полученные от провайдера токены и стоимость учитываются и при отклонённом содержимом ответа.

`pytest` автоматически отключает STT и автоматическую оценку импортов; специализированные проверки включают их только с подставленным транспортом. Проверки маскирования используют синтетический текст. Реальные ответы исследовательских звонков не копируются в репозиторий.

## Проверки

Из `backend` с активированным окружением:

```powershell
pytest -q
```

Без активации используйте `.\.venv\Scripts\python.exe -m pytest -q`. Провайдеры подставляются только внутри тестового приложения; платные запросы не выполняются.

Примеры одиночных запросов к работающему серверу:

```powershell
curl.exe http://localhost:8000/api/health
curl.exe "http://localhost:8000/api/conversations?language=RU&status=review"
curl.exe http://localhost:8000/api/conversations/p4-ru-001/audio -H "Range: bytes=0-1023" -D audio-headers.txt -o audio-part.mp3
```

Тесты OpenRouter используют подставленный HTTP-транспорт: проверяют структурные ответы, точные цитаты, исправление неверного результата, повторную проверку, usage и смену провайдера. Экспорт проверяется на синтетических полных наборах, апелляциях, ошибках модели и неверном JSON. Это функциональные проверки, а не замер точности на DEV. Доказательства интеграционных проверок и ограничения описаны в [TESTING.md](TESTING.md); цена и время полного прогона не выводятся из короткой пробы формата.

## Разрешение неоднозначностей контракта

- Поддерживается Python 3.10 по заданию пользователя; в первоначальном плане указан 3.11.
- При отсутствии применимых критериев `total` и `sections` равны `null`: это прямое правило раздела 3, хотя тип сущности для `sections` в разделе 2 записан как массив.
- Дополнения подэтапов сохранены: `transcriptHash`, `status=review`, `lastEvaluation.status=stale`, `needsReviewCount`, `Job.usage`, `gold.skipped`. В списке есть `summary`; `health.totalCostUsd` учитывает все записанные вызовы. Внутренние поля очереди в HTTP не выходят.
- По дополнительному требованию безопасности импорт возвращает `audioRejected`; недопустимые аудиоссылки не сохраняются. Доступ аудиопрокси ограничен HTTPS, настроенным списком хостов и публичными IP-адресами.
- `counts` реестра учитывает набор/язык/канал/поиск до применения фильтра состояния. `appealsOpen` содержит число диалогов с открытой апелляцией у последней оценки.
- Сводка, точность, операторы, сравнение и обычная выгрузка используют последние готовые оценки текущего транскрипта для выбранной версии. Строгий JSON для сдачи всегда использует версию 1. Для шкалы в сводке `yes` означает верхнюю ступень, `no` означает более низкую; `avgFraction` сохраняет долю выполнения.
- Если для сравнения нет пары числовых итогов, `avgDelta=null`; отсутствующий результат не заменяется нулём. `totalMae` считается только по полностью размеченным диалогам; частичная разметка участвует в точности отдельных критериев.
- Переиспользование ищет завершённые критерии с тем же `id`, `contentHash`, транскриптом и идентичностью судьи, в том числе в частично упавших оценках. После апелляции копируется исходный ответ модели.
