# DataAvengers — FastAPI + SQLite

Бэкенд для Python **3.10+**, один процесс. Все данные, оценки, задачи, апелляции, версии, ручная разметка и ИИ-кэш сохраняются в SQLite. Готовые шаги оценки не повторяются после перезапуска.

## Установка и запуск

Из папки `backend` в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --port 8000
```

Если активация окружения запрещена настройками PowerShell, используйте `.\.venv\Scripts\python.exe -m pip install -r requirements.txt` и `.\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000`.

Интерфейс: <http://localhost:8000/>. OpenAPI: <http://localhost:8000/docs>. Для доступа по сети добавьте `--host 0.0.0.0`. Не запускайте несколько `--workers`: очередь рассчитана на один процесс. CORS разрешает локальные `localhost` и `127.0.0.1` с любым портом.

Сервер раздаёт папку `../web`. Интерфейс подключает загрузку JSON и синхронизацию CRM к REST API. Оценки, апелляции и чек-листы интерфейса пока используют состояние браузера; полный набор серверных маршрутов доступен независимо через API.

Все изменяющие запросы требуют `Content-Type: application/json`, включая POST без параметров (передавайте `{}`). Исключение: `POST /api/gold` принимает `text/csv`. Неподходящий тип получает 415 `unsupported_media_type`. При наличии `Origin` разрешён тот же источник либо `http://localhost` / `http://127.0.0.1` с любым портом; без `Origin` заголовок `Sec-Fetch-Site`, если он есть, должен быть `same-origin`. Чужой источник получает 403 `forbidden_origin`. Серверные клиенты без обоих заголовков работают с указанным типом содержимого.

## Настройки

`.env` необязателен: значения по умолчанию позволяют запустить заглушку и импорт DEV. При необходимости скопируйте `.env.example` в `.env`. Пути разрешаются относительно `backend`, независимо от рабочей директории.

| Переменная | По умолчанию / назначение |
| --- | --- |
| `DB_PATH` | `./data/cqa.sqlite`, создаётся при запуске |
| `ORG_API_URL` | Ссылка организаторов без `group_id`; включена в `.env.example` и настройки по требованию задания |
| `AUDIO_ALLOWED_HOSTS` | `.environment.api.powerplatform.com,.dynamics.com` — разрешённые хосты/суффиксы аудио через запятую; пустое значение запрещает все аудиохосты |
| `JUDGE` | `fake` или `real`; по умолчанию `fake` |
| `JUDGE_CONCURRENCY` | `8`, общий предел одновременных вызовов судьи и ИИ-функций |
| `LLM_BASE_URL` | `https://api.openai.com/v1`, адрес совместимого API модели |
| `LLM_API_KEY` | Ключ настоящей модели, пустой для заглушки |
| `LLM_MODEL` | Имя настоящей модели, возвращаемое в оценках |
| `LLM_PRICE_IN`, `LLM_PRICE_OUT` | Доллары за миллион входных/выходных токенов, по умолчанию `0`; использует ML-адаптер |
| `FAKE_DELAY` | `0.4` секунды: заготовки отвечают за 0,4–1,2 с; в тестах задержка сокращена |
| `AUTO_SUMMARIZE` | `1`: после импорта резюме рассчитываются в фоне с более низким приоритетом, чем оценки; `0` отключает |

Таймаут одного вызова модели — 90 секунд; при HTTP 429 повтор через 2, 4, 8 секунд в пределах таймаута. Импорт организаторов: таймаут 60 секунд и один повтор. Запросы с телом ограничены 20 МБ, `gold.csv` — 5 МБ. `health` проверяет настоящую модель коротким запросом к `/chat/completions` с общим таймаутом 3 секунды и кэшем 20 секунд.

Аудиопрокси принимает только HTTPS. Хост после приведения к нижнему регистру и удаления конечной точки должен точно совпадать с разрешённым значением либо быть его поддоменом по границе точки. Проверяются страница плеера, адрес `<source>` после `urljoin` и каждый редирект (до трёх на цепочку). Перед подключением проверяются **все** адреса `getaddrinfo`: непубличные, частные, loopback, link-local, multicast, unspecified и reserved запрещены. Соединение идёт на проверенный IP с исходными Host и TLS SNI/проверкой сертификата, без повторного DNS-разрешения хоста и без прокси из переменных окружения. DNS-проверка ограничена 10 секундами. При импорте/загрузке недопустимая аудиоссылка заменяется на `null`; ответ содержит `audioRejected` — число таких ссылок, а аудиомаршрут возвращает `no_audio`. Остальные данные диалога сохраняются.

## Подключение модели

Общие Pydantic-модели находятся в `app/models.py`: Python-атрибуты в `snake_case`, HTTP-поля в `camelCase`. Исключение `JudgeError` определено в `app/errors.py`. Судья получает `Conversation` и `Criterion`, возвращает `JudgeResult` с `Usage`, реальным именем модели и временем вызова.

1. Подставьте функции `async judge(conversation, criterion)` и `async second_opinion(conversation, criterion, original, appeal_comment)` в **`app/judge/__init__.py`**. Сейчас файл явно реэкспортирует fake, поэтому `JUDGE=real` тоже запускается до прихода ML-кода. При подключении реального кода удалите реэкспорт `IS_FAKE` либо задайте `IS_FAKE = False`.
2. ML-команда размещает общий API-клиент/расчёт стоимости в `app/judge/llm.py`. Бэкенд не содержит промптов и не подменяет эту реализацию.
3. Подставьте `summarize`, `translate`, `coach`, `suggest_criterion` в **`app/ai/__init__.py`**, также убрав `IS_FAKE` для настоящих функций.
4. Установите `JUDGE=real`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` и тарифы, перезапустите сервер.

Сигнатуры соответствуют разделу 6 контракта. Для неоднозначного «список переводов и usage» предусмотрен тип `Translation(turns, usage)`; адаптер также принимает `(turns, usage)` или список `TranslatedTurn`. У `coach` и `suggest_criterion` контракт не задаёт `usage`: при его отсутствии учитывается один вызов с нулевыми токенами/стоимостью. Если нужны точные суммы этих функций, ML-команда должна согласовать расширение возвращаемого типа. Заглушки не выдают фиктивную стоимость.

При ошибке импорта реального модуля включается fake, ошибка фиксируется в серверном логе, а `health.modelOnline` становится `false`. При штатном временном реэкспорте fake поле `model` честно равно `fake`.

Заготовки судьи сохранены один раз из `web/data/mock-evaluations.js` в `app/judge/fixtures.json`; Node.js при работе сервера не нужен. Поддерживаются ровно пять диалогов:

`p1-ru-001`, `p1-ru-007`, `p1-kz-003`, `p1-en-002`, `p4-ru-001`.

Для остальных диалогов и новых неизвестных критериев fake бросает `JudgeError`. Автоматические резюме остальных 60 диалогов поэтому отсутствуют до подключения реального ИИ. Кэш можно пересчитать через `?refresh=1`, в том числе после замены fake на настоящую модель. Повторная оценка с `reuse=false` вызывает настоящую модель по всем критериям.

## Источник CRM и повторная синхронизация

Таблица `settings` хранит `sourceGroupId` (по умолчанию `DEV`), `lastSyncAt` и `lastResult`. До первого успеха последние два поля равны `null`. Смена набора сбрасывает сведения о последней синхронизации; повторное сохранение того же набора их сохраняет. Настройки переживают перезапуск сервера.

Каждая синхронизация заново обращается к API организаторов с сохранённым `group_id`. Дедупликация общая для файла и CRM по `conversation_id`: новый диалог добавляется, изменённый транскрипт обновляется, неизменный входит в `unchanged`. Старая оценка сохраняется в истории и получает `lastEvaluation.status=stale` в реестре; её снимок транскрипта не меняется. При неизменном транскрипте сохраняются время импорта и актуальность оценки. Метаданные источника и аудиоссылки могут обновляться. Удаление записи из внешнего набора не удаляет её из реестра.

Обычный `POST /api/source/sync` возвращает JSON после завершения. Для прогресса интерфейс передаёт `Accept: application/x-ndjson`: события `fetching`, затем `importing` с `processed` и `total`, затем `done` с `result`. Счётчик отражает обработанные записи; успех отправляется только после фиксации транзакции. Событие `error` содержит безопасную ошибку «CRM не ответила. Попробуйте ещё раз через минуту». При ошибке прошлый успешный результат остаётся сохранённым. Синхронизации и смена источника выполняются последовательно, импорт записей и сохранение результата атомарны. Старые `/api/datasets/import` и `/api/conversations/upload` сохраняют формат ответов.

## Проверки

Из `backend` с активированным окружением:

```powershell
pytest -q
# При работающем сервере: реальные запросы через curl, изменяют локальную БД.
python scripts/smoke.py
```

Без активации используйте `.\.venv\Scripts\python.exe -m pytest -q` и `.\.venv\Scripts\python.exe scripts/smoke.py`. `smoke.py` вызывает `curl.exe`/`curl`, импортирует живой DEV (при недоступности — `tests/data/dev.json`), оценивает пять диалогов и опрашивает задачу, решает апелляцию, создаёт версию, проверяет reuse/compare, выгрузки, ИИ-маршруты и реальное аудио 206. Артефакты сохраняются в игнорируемую `verification/`.

Примеры одиночных запросов:

```powershell
curl.exe http://localhost:8000/api/health
curl.exe "http://localhost:8000/api/conversations?language=RU&status=review"
curl.exe -X POST http://localhost:8000/api/conversations/upload -H "Content-Type: application/json" --data-binary "@tests/data/dev.json"
```

Последняя проверка: **167 pytest-тестов прошли**, включая защиту аудио от SSRF, 82,94, все N/A, апелляции 88,82/85,50, продолжение после перезапуска, частичные результаты, retry, reuse без модели, кэш, валидацию и формы HTTP-ответов. Живой DEV импортирован: 65 записей. После добавления защиты аудио повторно вернуло **206, 1024 байта**, `Content-Range: bytes 0-1023/1921932`. Подробности: `TESTING.md`.

## Разрешение неоднозначностей контракта

- Используется Python 3.10 по заданию пользователя (в плане указан 3.11), пять заготовок из существующего JS (в старом тексте плана упомянуто шесть).
- При отсутствии применимых критериев `total` и `sections` равны `null`: это прямое правило раздела 3, хотя тип сущности для `sections` в разделе 2 записан как массив.
- Дополнения подэтапов сохранены: `transcriptHash`, `status=review`, `lastEvaluation.status=stale`, `needsReviewCount`, `Job.usage`, `gold.skipped`. В списке есть `summary`; `health.totalCostUsd` учитывает все записанные вызовы. Внутренние поля очереди в HTTP не выходят.
- По дополнительному требованию безопасности импорт возвращает `audioRejected`; недопустимые аудиоссылки не сохраняются. Доступ аудиопрокси ограничен HTTPS, настроенным списком хостов и публичными IP-адресами.
- `counts` реестра учитывает набор/язык/канал/поиск до применения фильтра состояния. `appealsOpen` — число диалогов с открытой апелляцией у последней оценки.
- Сводка, точность, операторы, сравнение и выгрузка используют последние готовые оценки текущего транскрипта для выбранной версии. Для шкалы в сводке `yes` означает верхнюю ступень, `no` — более низкую; `avgFraction` сохраняет долю выполнения.
- Если для сравнения нет пары числовых итогов, `avgDelta=null`; отсутствующий результат не заменяется нулём. `totalMae` считается только по полностью размеченным диалогам; частичная разметка участвует в точности отдельных критериев.
- Переиспользование ищет завершённые критерии с тем же `id`, `contentHash` и транскриптом, в том числе в частично упавших оценках, как предписывает подэтап 02.3. После апелляции копируется исходный ответ модели.

Других намеренных отклонений от согласованных маршрутов и правил нет. Реальный ML-провайдер не подключён: точки интеграции готовы, функциональные проверки выполнены на предусмотренных заглушках.
